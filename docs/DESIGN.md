# Tidebound — Design

Tidebound is a browser-native reimagining of the "puzzle pirate" MMO formula:
a persistent ocean of islands, crews that sail ships together, and a set of
**duty puzzles** whose results physically drive the ship. Everything runs on
modern web tech: TypeScript end to end, Vite + React + Canvas 2D on the client,
a Node WebSocket server with an authoritative world, and a shared package of
pure, deterministic game engines so the server can replay what the client did.

## Pillars

1. **Puzzles are the verbs.** Every action in the world (pumping water, trimming
   sails, loading cannons, fixing the hull, plotting a course, fighting) is a
   puzzle. Puzzle quality feeds directly into ship stats and battle outcomes.
2. **Together on a ship.** The ship is the social unit. A crew boards, takes
   stations, and the captain steers on the hex ocean. Everyone's performance is
   visible on the duty report.
3. **Deterministic cores.** Every puzzle engine is a pure reducer:
   `init(seed) -> reduce(state, action) -> tick(state, dt)`. The client records
   an action log; the server replays it on the same seed to verify the score.
4. **Readable at a glance.** A warm, hand-drawn-adjacent aesthetic: parchment UI,
   deep ocean blues, brass accents, chunky readable puzzle pieces. No generic
   dark-mode-SaaS look.

## Packages

- `packages/shared` — engines, protocol (zod), world data, hex math, RNG.
- `packages/server` — `ws` server. Rooms: `IslandRoom`, `ShipRoom`, `BattleRoom`.
  Persistence: JSON snapshot in `data/world.json`.
- `packages/client` — React shell, Zustand store, Canvas scenes & puzzle renderers.

## Puzzle contract

```ts
interface PuzzleDef<S, A> {
  id: PuzzleId;
  name: string;
  init(seed: number, config?: PuzzleConfig): S;
  reduce(state: S, action: A): S;     // pure; illegal actions are a no-op
  tick(state: S, dtMs: number): S;    // pure time step (integer ms)
  isOver(state: S): boolean;
  score(state: S): PuzzleScore;       // { points, performance (0..1) }
}
```

- `performance` is a smoothed, recent-window rating in 0..1 used by the ship.
- Engines must not use `Math.random`; they draw from `state.rng` (mulberry32 seeded).
- Engines must be JSON-serialisable (plain objects/arrays, no classes, no Maps).
- `reduce` must return the same reference when nothing changed.

## Puzzles

| Station     | Puzzle                                   | Ship effect                         |
|-------------|------------------------------------------|-------------------------------------|
| Bilge       | Match-3 swap, water rising, crabs/puffers| Bilge level → speed penalty         |
| Sails       | Columns-style falling triples            | Sail power → move tokens per turn   |
| Carpentry   | Polyomino hull patching                  | Hull repair → damage removed        |
| Guns        | Line-clear stacking with powder/shot     | Cannons loaded → shots per turn     |
| Navigation  | Star chart pipe rotation                 | Nav bonus → extra token / accuracy  |
| Swordfight  | Puyo-style versus with breakers (PvP/PvE)| Boarding outcome                    |

## Ocean & battle

- The ocean is a hex grid (axial coords). Islands occupy cells; ships move on
  the water. Voyages are navigated by the captain on the ocean map.
- Random brigand encounters start a **sea battle**: 24x24 hex board, 20s turns.
  Each turn the captain queues up to 4 move tokens (L/F/R) generated by Sails,
  and cannon shots (port/starboard) loaded by Guns. Damage is reduced by Bilge
  (speed) and Carpentry (repair).
- Grapple when adjacent after moves → **boarding** → swordfight (crew vs. crew,
  NPC AI for brigands). Winner takes booty (pieces of eight + commodities).

## Protocol

JSON over WebSocket. Every message is `{ t: string, ...payload }`. Client→server
messages are validated with zod (`ClientMsg`), server→client typed as `ServerMsg`.
See `packages/shared/src/protocol.ts`.
